- 2026-11-16 — [ADR-0011](ADR-0011%20FIFO%20Per-Wallet%20Chain%20Without%20Hold.md) set to **Accepted**. Added a **Finding** from the hub backend (`hub/apps/backend`, NVNM write path): THE HUB already serialises writes per signing wallet via the durable `wallet_tx_jobs` queue — enqueue depth guard under `pg_advisory_xact_lock(walletId)` (over depth → `BLOCKCHAIN_WALLET_TX_QUEUE_FULL`/503), `claimNextRunnableJob` takes one job per wallet via `NOT EXISTS` on blocking statuses (`Processing/Signing/SignedPendingSubmit`) with `FOR UPDATE SKIP LOCKED`, and nonce ordering (sequential `getTransactionCount('latest')` + per-wallet mutex, self-healing `nonce too low` retry; batch assigns sequential nonces + waits pending-nonce/receipt). So the IO Hub FIFO group is **ordering + backpressure only, not nonce-safety**; this settles the `regular` "fly-through" concern (fast ack is fine, the write still serialises per wallet inside THE HUB). Backpressure and Consequences wording updated to reference the Finding.
- 2026-11-16 — [ADR-0011](ADR-0011%20FIFO%20Per-Wallet%20Chain%20Without%20Hold.md) Finding: clarified the hub overflow. The 503 (`BLOCKCHAIN_WALLET_TX_QUEUE_FULL`) is **per signing wallet**, triggered when non-terminal jobs (`Queued/Processing/Signing/SignedPendingSubmit`) for one wallet reach `maxDepth` (default **50000**, config `walletTxQueue.maxDepth`); terminal jobs don't count, so the queue drains as it finishes. It is a safety ceiling for abnormal single-wallet pile-up, not routine per-file backpressure, and is distinct from `maxInFlight` (16, worker concurrency) / `ledgerRpcMaxInFlight` (NVNM 4).
- 2026-11-16 — [ADR-0011](ADR-0011%20FIFO%20Per-Wallet%20Chain%20Without%20Hold.md): recorded a confirmed blocker for the 503→requeue path. THE HUB returns a genuine `503` for queue-full (`BLOCKCHAIN_WALLET_TX_QUEUE_FULL` 1298), but IO Hub `HubTokenizationProvider.write` rethrows every write error as `UnprocessableEntityException` (422), discarding the 503 (`inveniam.io/apps/hub-service/src/tokenization/hub-tokenization.provider.ts`, test confirms). 503→422 kills retry semantics, so the requeue-to-tail trigger can't fire end-to-end. Added to ADR-0011 open threads + Affected code (`hub-tokenization.provider.ts` write: stop masking 503, propagate 503/429 or a marker) and strengthened Open Questions #6 prerequisite.
- 2026-11-16 — [ADR-0011](ADR-0011%20FIFO%20Per-Wallet%20Chain%20Without%20Hold.md) Decision: sharpened the translator rule after reading the sagas (`apps/hub-service/.../sagas/`). Each chain step is `broker event → @Saga → in-process CQRS command`; the commands (`RunPortfolioProvisioningCommand`, `StoreDealAnchorRegistryCommand`, `RunDocumentProvisioningCommand`, `RegisterSymbolCommand`, `SyncDocumentCommand`, `UpdateTxStatusCommand`) carry no `MessageGroupId`, are already hub-private, and need **no** rename/`Internal`. Only saga-subscribed broker events need the wallet group, and because the chain parks and resumes on THE HUB's webhook as a new broker message, the group must be re-established at **each** public hop: `ClientDLTTransaction`, `HubSymbolRegisteringSucceededEvent`, `HubDocumentSyncingRequestedEvent` — all three fanned, so each gets an `Internal` twin, not only `ClientDLTTransaction`.
- 2026-11-16 — Proposed [ADR-0012 Durable Workflows Engine](ADR-0012%20Durable%20Workflows%20Engine.md) and [ADR-0013 Hybrid Workflows Over Hub Queue](ADR-0013%20Hybrid%20Workflows%20Over%20Hub%20Queue.md) after studying NestJS [Durable workflows](https://docs.nestjs.com/reliability/workflows) + [Durable sagas](https://docs.nestjs.com/recipes/cqrs#durable-sagas). So it is named as the long-term engine, gated on a NestJS/cqrs upgrade + fork-reconciliation spike, not adopted. ADR-0013 (hybrid, user's direction — not a replacement): THE HUB keeps nonce-safety (`wallet_tx_jobs`); IO Hub owns orchestration + durability via a per-file workflow with `concurrency.key` serialisation and `waitForSignal` parking; the public event contract stays. Migration: FIFO (ADR-0011) now as the serialiser → spike → workflows later. Per the follow-up, workflows are an **addition**, not a forced replacement: the FIFO group may be retired or kept for broker-level ordering/backpressure; cutover picks a lane per source/environment to avoid redundant double-gating. THE HUB queue stays the nonce-safe writer in every option. ADR-0011 set to Accepted and badged accordingly. INDEX updated with both new rows.
