## What the feature is (one paragraph)

[ADR-0003 Shared Redis Forget Set](../decisions/ADR-0003%20Shared%20Redis%20Forget%20Set.md) (Accepted, supersedes ADR-0001/0002): after a person is erased (`POST /v1/erasures`, Vault crypto-shred + Postgres `erasure_ledger` row), two holes remain — a sibling replica's warm DEK cache still decrypts old events (DP-001), and ingest re-mints a subject key so the erased person looks new (DP-002). Fix: one global Redis set `sidecar:forgotten` (same Redis as idempotency), member `company_id|subject_pseudonym`. Erase = Vault destroy → ledger insert → `SADD` (never `SADD` if insert fails). Ingest and read = `SISMEMBER` **before** `SealEvent`/`OpenEvent`. Empty set = heal from Postgres via **`ListAllErasures`** (all tenants — per-company hydrate poisons the heal), `SADD` on top, union only, never `SREM`/`DEL`.
